# 微信版本适配模块

每个微信版本使用自己的目录。版本相关的 DLL 指纹、原生入口 RVA、函数前缀、对象布局和 Frida 适配代码放在该目录内，公共运行层通过 `src/native-compat.mjs` 的固定注册表选择模块。

```text
wechat-adapters/
├─ 4.1.15.13/
│  ├─ index.mjs
│  ├─ profile.json
│  ├─ read-agent.js
│  ├─ send-agent.js
│  └─ receive-agent.js
└─ 4.2.0.7/
   ├─ index.mjs
   ├─ profile.json
   ├─ read-agent.js
   └─ send-agent.js
```

| 文件 | 内容 |
| --- | --- |
| `index.mjs` | 版本、DLL SHA-256、模块路径、入口地址及可复用证据的约束 |
| `profile.json` | 精确二进制指纹及该版本独立取得的原生验证记录 |
| `read-agent.js` | 当前账号、联系人缓存和最近历史的原生调用、地址与布局校验 |
| `send-agent.js` | 单目标文字和图片发送的原生调用、回调所有权及结果结构 |
| `receive-agent.js` | 4.1 保留的 AddMsg 接收研究代码；当前未声明该钩子已验证 |

`src/` 负责进程发现、宿主、账号和目标授权、请求账本及公共 DTO 校验。`agents/inspect.js` 只读取模块元数据，不包含版本业务入口。原生 RPC 脚本名可以跨版本相同，但每个宿主只加载与当前版本及指纹匹配的适配源码，并校验其源哈希。

## 已验证范围

| 微信 x64 版本 | 账号、联系人、历史 | 文字发送 | PNG 图片发送 | AddMsg 实时钩子 |
| --- | --- | --- | --- | --- |
| 4.1.15.13 | 已验证 | 已验证 | 已验证 | 未验证 |
| 4.2.0.7 | 已验证 | 已验证 | 已验证 | 未验证 |

4.2.0.7 在 2026-10-25 完成真机验证：文件传输助手的文字消息通过本人历史回显核对；PNG 通过新增类型 3 消息、当前本人方向和图片 MD5 核对。原生历史 API 按需读取记录，不依赖 AddMsg 钩子。数据库自动取钥与解密的已有真机记录为 4.1.15.13，不能由上述读写验证推断其他版本的数据库流程也已验证。

`profile.json` 的二进制证据只证明该 DLL 的接口已做过验证，不包含个人收件人、登录状态或未来消息的送达保证。每台电脑仍须重新核验当前账号、主进程、运行代次及精确目标。

## 添加新版本

1. 新建 `wechat-adapters/<完整微信版本>/`，记录实际 x64 DLL 的 SHA-256。
2. 独立定位账号、联系人、历史、文字和图片所需的入口与布局；核对函数前缀、任务上下文、系统导入、对象和回调所有权。不要只替换版本字符串或沿用旧 RVA。
3. 编写该版本的 `index.mjs`、`profile.json`、`read-agent.js`、`send-agent.js`，并在公共固定注册表中显式登记。没有验证的能力保持关闭，不从旧版复制成功验证记录。
4. 为新版本添加离线测试，覆盖字段解码、版本和指纹拒绝、账号与目标变化、取消、未知结果、目录路径和源码哈希验证；保留已有版本回归测试。
5. 在匹配的真实客户端先验证只读路径，再明确向自己的文件传输助手验证文字和有效 PNG，并独立回读核对。只有取得真实证据后才填写该二进制对应的验证记录。
6. 更新本说明与相关命令文档，执行 `npm test` 并核对提交内容。个人配置、聊天记录、Token、宿主描述和目标绑定放在本机忽略目录，不加入模块或提交。

未知版本或不同 DLL 指纹会被拒绝。将文件夹改名、放宽路径检查或填写旧版成功证据，均不能完成新版本适配。
